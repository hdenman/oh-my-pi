# Local binary builds — Darwin + Linux (2026-08-28)

`nix-shell && bun run build:local` produces `~/.local/bin/omp.<sha>.<date>`
and atomically re-links `~/.local/bin/omp`.

## Files

- `shell.nix` — reproducible shell (bun 1.4.0, bazelisk, rustup, libopus, cmake, pkg-config)
- `scripts/build-local.ts` — build orchestrator (already existed; patched below)

## shell.nix design

**Pinned nixpkgs-unstable** @ `ede7a04c7ae5` (2026-05-03, sha256 `1l1svkxkas9irwk...`).
Current nixpkgs has bun 1.3.13; overlay adds 1.4.0 with per-platform sources.

**bun 1.4.0 overlay** — must override three things:
1. `version` + per-platform `src` attrset keyed by `stdenv.hostPlatform.system`
2. `postPhases = [ ]` and `postPatchelf = ""` — upstream `postPatchelf` runs `bun completions`
   inside the nix sandbox, which always fails for version bumps (binary must execute).
   We don't need shell completions.
3. x86_64-linux uses `bun-linux-x64-baseline.zip` (no AVX2) — required for older CPUs
   (e.g. Celeron J3455 / Goldmont).

**Why 1.4.0, not 1.3.14** — bun 1.3.14 has issue #31023: `patchelf` (used by nixpkgs
`autoPatchelfHook`) inserts an extra writable `PT_LOAD` at the front of the program-header
table; `write_bun_section` picked the wrong segment, producing compiled binaries whose
PT_LOADs overlap and SIGSEGV at execve. Fixed in 1.4.0 PR #31024.

**bazelisk** — nixpkgs has 1.25+; reads `.bazelversion` → downloads Bazel 9.2.0 on first use.
Wrapped as `bazel` via `writeShellScriptBin` (bazelisk binary is named `bazelisk`).

**rustup** — not in the shell as a managed toolchain; `shellHook` runs
`rustup toolchain install nightly-2026-04-29 --profile minimal` if absent.
Cargo ends up at `~/.cargo/bin`; build-local.ts finds it there.

**libopus + pkg-config** — `audiopus_sys` (crate dep) tries cmake to build bundled opus
when pkg-config doesn't find it. `PKG_CONFIG_PATH` set in shellHook to the nix libopus
`.dev` output → pkg-config path found → cmake skipped entirely. cmake still included as
fallback.

## build-local.ts change

Original code called `napi build --platform --release` directly, outputting
`pi_natives.linux-x64-gnu.node`. `embed-native.ts` (gen:native) expects
`pi_natives.linux-x64-baseline.node` or `pi_natives.linux-x64-modern.node` on x64.

Fix: delegate to `bun --cwd=packages/natives run build:bindings` which:
- detects AVX2 → selects `baseline` or `modern` variant
- sets `RUSTFLAGS=-C target-cpu=x86-64-v2` for baseline
- renames `pi_natives.linux-x64-gnu.node` → `pi_natives.linux-x64-baseline.node`

Sentinel check updated: was checking `pi_natives.linux-x64.node` (no variant); now checks
`pi_natives.linux-x64-baseline.node` (or `modern`) by calling `detectHostAvx2Support()`
from `scripts/host-detect.ts`.

## Iteration log

| Round | Problem | Fix |
|---|---|---|
| 1 | Linux tried to build darwin-aarch64 Mach-O | Per-platform `src` attrset |
| 2 | `postPatchelf` ran `bun completions` in sandbox, failed | `postPhases = [ ]; postPatchelf = ""` |
| 3 | Celeron J3455 SIGILL (`x64` build needs AVX2) | Switch x86_64-linux to `x64-baseline` |
| 4 | No cargo on Linux | Add rustup + shellHook toolchain install |
| 5 | `audiopus_sys` cmake not found | Add libopus, pkg-config; set `PKG_CONFIG_PATH` |
| 6 | `gen:native` failed: `pi_natives.linux-x64-baseline.node` not found | Delegate rebuild to `build:bindings` |
| 7 | Compiled binary SIGSEGV on Linux (bun #31023) | Bump bun 1.3.14 → 1.4.0 |

## Usage

```sh
nix-shell          # enters shell with bun 1.4.0, bazelisk, rustup
bun run build:local
```

First run on a fresh Linux box takes ~25 min (full Rust compile). Subsequent runs
skip the cargo step if the sentinel matches.

## Updating bun version

1. Hash the new zips: `nix-prefetch-url --type sha256 <url>`
2. Convert to SRI: `nix-hash --type sha256 --to-sri <hash>`
3. Update `version` + all three `hash` fields in `shell.nix`
4. Update `"packageManager"` in `package.json`
