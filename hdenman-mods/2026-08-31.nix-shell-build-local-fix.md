# Native build sentinel and build.rs fixes (2026-08-31)

Fixes for `nix-shell --command "bun run build:local"` failures and incremental build performance.

## Root Causes & Fixes

1. **`pi_natives` x64 GNU addon filename detection in `scripts/build-local.ts`**:
   `scripts/build-local.ts` checked for the prebuilt native addon sentinel using `pi_natives.${platformTag}.node`.
   On Linux x64, `napi build` generates `pi_natives.linux-x64-gnu.node` (or `pi_natives.linux-x64-baseline.node`).
   Because `pi_natives.linux-x64.node` was missing, `sentinelFound` always evaluated to `false`, forcing `build-local.ts` to trigger a full `napi build` on every execution even when the binary was already compiled.

   *Fix*: Updated `scripts/build-local.ts` to check for `pi_natives.${platformTag}-gnu.node` on x64 platforms. When `grep` finds the sentinel (`__piNativesV18_0_10`), `build-local.ts` skips re-compiling native code.

2. **Orphaned minimizer build step in `crates/pi-natives/build.rs`**:
   `crates/pi-natives/build.rs` contained an obsolete `generate_minimizer_builtin_filters()` function that attempted to read filter definitions from `crates/pi-natives/src/shell/minimizer/defs`. Shell minimizer definition files live under `crates/pi-shell`, not `crates/pi-natives`.

   *Fix*: Removed `generate_minimizer_builtin_filters()` from `crates/pi-natives/build.rs`, simplifying `main()` to only call `napi_build::setup()`.

## Verification

Ran `nix-shell --command "bun run build:local"` end-to-end:
- Verified sentinel detection skipped unnecessary native recompilations.
- Embedded assets generated cleanly.
- `~/.local/bin/omp` built and installed successfully.
- Verified version with `~/.local/bin/omp --version` (`omp/18.0.10`).
